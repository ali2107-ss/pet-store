# Локальная разработка и настройка Supabase

Короткая инструкция для команды, чтобы каждый мог запустить проект локально и продолжать разработку без утечки секретов.

- **Переменные окружения:** поместите эти переменные в файл ` .env.local` (в корневой папке проекта):

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...anon_key...
# (Опционально, ТОЛЬКО на сервере) SUPABASE_SERVICE_ROLE_KEY=eyJ...service_role_key...
```

- **Важно:** `SUPABASE_SERVICE_ROLE_KEY` — это привилегированный ключ. Никогда не храните его в клиентских файлах и не коммитьте в репозиторий.

- **Создание `.env.local`:** просто создайте файл ` .env.local` и вставьте значения. В репозитории есть `env.example` — его можно скопировать и заполнить.

- **Установка зависимостей и запуск (PowerShell):**

```powershell
npm install
npm run dev
```

 **Redirect URLs (для OAuth):** если вы используете авторизацию через провайдеров (Google, GitHub и т.д.), в Supabase Dashboard добавьте `http://localhost:3000` в `Authentication → Settings → Redirect URLs`.
 **Проверка доступа к данным (RLS):** если в таблицах включён Row Level Security (RLS), убедитесь, что у вас есть политики для `authenticated` пользователей (или нужных ролей). Без корректных политик данные могут быть недоступны после логина.

 ## Быстрая настройка профилей (рекомендуется)

 Чтобы хранить расширенные данные пользователя (имя, телефон, аватар и т.д.), создайте таблицу `profiles` в Supabase. В репозитории есть SQL-скрипт с нужными командами: `db/supabase_profiles.sql`.

 Шаги для команды:

 1) Откройте Supabase → SQL Editor и выполните содержимое `db/supabase_profiles.sql`.
   - Скрипт создаст таблицу `profiles`, триггер для автоматического добавления записи при регистрации, и базовые RLS-политики.
 2) Если вы предпочитаете GUI: можно вручную создать таблицу `profiles` и добавить политики `select/update/insert` где `auth.uid() = id`.

 Примечание о регистрации: при регистрации через email подтверждение может быть включено — тогда пользователь получит письмо подтверждения и профиль создастся триггером после подтверждения (или будет создан сразу в зависимости от настроек). Если вы хотите, чтобы профиль создавался сразу при регистрации без подтверждения — настройте Authentication → Settings.

 Если хотите — я могу сгенерировать SQL ещё раз под ваши конкретные требования (доп. поля, адреса, заказы и т.д.).

## Server-side auto-confirm (рекомендовано для команды)

Если нужно, чтобы новые пользователи создавались сразу как подтверждённые и профиль формировался автоматически без ручного подтверждения — используйте server-side flow с `SUPABASE_SERVICE_ROLE_KEY`.

1) Добавьте в `.env.local` (ТОЛЬКО на сервере/локально у разработчиков, не коммите):

```dotenv
SUPABASE_SERVICE_ROLE_KEY=eyJ...service_role_key...
```

2) В репозитории добавлен endpoint `POST /api/admin/create-user` (`app/api/admin/create-user/route.ts`). Он создаёт подтверждённого пользователя и сразу upsert'ит запись в `profiles` (использует service role key и обходит RLS).

3) Безопасность: храните `SUPABASE_SERVICE_ROLE_KEY` только в `.env.local` на доверенных машинах или в секретах хостинга (Vercel/Netlify). Никогда не выкладывайте его в публичный репозиторий.

4) Если хотите — могу также изменить фронтенд, чтобы при регистрации вызывался этот серверный endpoint (уже сделано в `app/login/page.tsx`).

## Для членов команды без доступа к Dashboard (Вариант 3 — рекомендуется)

Если вы не хотите давать коллегам доступ к Supabase Dashboard, они смогут работать используя только публичный (anon) ключ. Это безопасный и эффективный способ для разработки.

### Что передать коллегам

1. **Клонировать репозиторий:**
```bash
git clone <ваш-repo-url>
cd pet-store
```

2. **Создать `.env.local` в корне проекта и вставить:**
```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...anon_key...
```

3. **Запустить проект:**
```powershell
npm install
npm run dev
```

4. **Работать с приложением:**
   - Открыть `http://localhost:3000`
   - Регистрация/вход через `/login`
   - Просмотр животных (`/animals`), оформление заказов, профиль

### Приглашение в Supabase Members (если нужен Dashboard доступ)

Для коллег, которым нужен доступ к Database структуре и SQL:

1. Откройте Supabase → Project → **Settings** → **Members**
2. Нажмите **Add member** или **Invite**
3. Введите email коллеги
4. Выберите роль: **Developer** (полный доступ, кроме биллинга) или **Viewer** (только просмотр)
5. Нажмите Invite
6. Коллега получит письмо с приглашением

После этого он сможет видеть таблицы, запускать SQL, редактировать политики и т.д.
